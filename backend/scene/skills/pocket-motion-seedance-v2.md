# Pocket Motion (Seedance) v2

```
1  inputs + assets   audio, script (+ .srt) → inventory + location sheets → the one stop (+ two reviews: anchors, clips)
2  map + listen      import user images to the Frameo CDN → map → improve locations? (yes → image-reconstruct) → resize to 1500 px; one audio analysis → transcript + sound list → measured speech spans of the character lines
3  anchor            one wide anchor still per staging state, everyone in place; camera setups written against it
4  plan              shot size line by line from the words, one shot per clause; each unit = a setup + a shot size + an angle + an action + a face + a camera move
5  generate          sheets + plates for the gaps, then the anchors; time the units; group them into chunks of ≤ 15 s; cut each chunk's slice of the master audio; build each narration chunk's timing track; one call per chunk on the chosen video model (narration chunks: an edit of their timing track)
6  render            lips aligned to the master voice → each chunk trimmed (and retimed) to its measured span → join + master audio (+ subs) + proof sheets
```

**Rules.** **Models are the user's choice, asked once — never hard-coded.** This skill fixes no image or video model. In the Step 1 message the user picks one image model and one video model from the studio's own list (**Pick the models**, Step 1), and the run then uses exactly those two: every image — sheets, plates, anchors, re-rolls and edits — on the chosen image model; every video — every chunk and every re-roll — on the chosen video model. Save the pick to `/motion/decisions` as `image_model` and `video_model` (workflow id and title) and write that workflow id out on every call — never omitted, never left to the studio's default, never swapped mid-run. If the user later names another model, say which sheets, plates, anchors or chunks were made on the old one and how many would be redone, and redo nothing until they confirm. If a chosen model is gone or fails, stop and ask the user to pick again from the list — never fall back to another on your own. Settings, on whichever model is picked: images at its draft (lowest) quality, `1:1` at the largest size it offers up to 2K — except anchors, always `16:9`, to hold the whole scene. Video at `480p`, plus — for a dialogue chunk — `1:1` with the model's own sound on (where it has that setting), or — for a track chunk (5.4) — sound off, no aspect ratio (the edit takes its track's shape) and `duration` = the track's length rounded up to a whole second. A setting the chosen model does not have is left out, never written into the prompt instead. **Fit the plan to the chosen video model:** before 5.4, read its limits from the studio's workflow list — the longest clip, the reference image and audio slots, whether it takes a reference video — A chunk is at most 15 s, the longest MiniMax H3 clip, and less when the chosen model's longest clip is shorter; it never carries more reference images than the model has slots (H3 Director: 6 — background, three characters, outfit, prop). The `go` in Step 1 is the user's confirmation of the models, duration, aspect ratio and audio for every chunk; never ask again per call. The one exception to the image model is the location rebuild in step 2 (**Improve locations?**), which runs `image-reconstruct` with that skill's own model, checks and steps. The master audio is never edited and is the film's only audio track: the audio a chunk generates is always dropped at render. Anchors are references only: they are never placed on the timeline or shown in the film. This skill overrides output verification: never view a generated sheet, plate or clip — the anchors in 5.2 are the one exception; review is the user's — at the anchor review (5.2), the clips review (5.6) and via the proof sheets; re-roll only what they name. Never call `load_skill` during this run — not `ffmpeg-recipes`, not a video guide, not any other, except `image-reconstruct` when the user answers **Yes** to **Improve locations?**: the prompt rules in 5.5 are complete and are followed exactly as written. Never call `creative_direction_guide` — the plan, anchors, setups and prompts are written by you, here.

**In this studio (Scene.ai).** This skill was written for other tools. Wherever it names one, use the studio's tool below; never call a tool the studio does not have, and never write ffmpeg arguments or a script yourself. The workflows named here are the studio's own (its workflow list has them); the user still picks the models in Step 1, and these are the ones to recommend.

Its `aspect_ratio` setting gives 1:1 = 1536×1536, 16:9 = 2752×1536 (the anchor's size), 9:16, 4:3; its `quality` is `draft` (this skill's `low`, about 16 s) or `final` (about 3.5 min). A chunk with no line spoken on screen gets no voice track and `402:value` (KEEP GENERATED SOUND) = `false`: its own sound is never used, and skipping it is faster. ## 1 — Inputs and assets

**Inputs:** master audio (final mix); script (location cues, `NAME:` dialogue, unattributed narration, optional `SFX:` cues; typos fixed inline as `[FIXED: was "…"]`); optional `.srt` on the master's clock.

**Audio and script are mandatory — check before anything else.** Both must be attached or pasted in this chat before any tool call, inventory or state write. If either is missing, the only response is one short message naming what is missing ("I need the episode audio (final mix) and the full script to start — please attach both.") and the turn ends; run nothing, plan nothing, generate nothing. A transcript, an `.srt`, a summary or a partial script is not the script; a single stem is not the master audio. Only when both are in does Step 1 start — and its first act is saving them: `/motion/inputs/audio` (CDN link, duration, frame count), `/motion/inputs/script` (full text), plus `/motion/inputs/csv` / `/motion/inputs/srt` when given (later uploads are saved the moment they arrive). The inventory is saved to `/motion/assets/inventory`.

**Inventory, from the script before any tool:** characters (speaking or present; exposition-only people to be pictured, tagged), locations (staged; exposition-only; implied off-screen) with their light states, props (carried, handled, or seen twice). Each character also gets a **look list**, in script order: `base`, then every visible change the story makes to them — an injury, a stain, torn or wet clothes, a new outfit, a haircut, anything taken off or put on (a turban removed, a jacket off, a garland, jewellery or a uniform put on) — each named (`bruised`, `bruised+new_shirt`, `no_turban`) with the beat it starts at and one line of what changed. Read the narration and dialogue for it, not only stage cues ("he tore off his turban", "she wrapped the shawl around herself"); a change back (turban on again) is a new look too. A look holds from its beat until the script changes it again; it never fades or resets on its own — every unit, anchor and chunk after the beat shows it. A character seen in a flashback gets the look of the time it shows — its own named look (`young`, `pre_war`) when the script pictures them differently then — tagged `flashback`. One visual line each — ethnicity from setting and names, wardrobe from the script, "hair neatly styled", a prop's material/colour/shape. Visual lines feed sheet and plate prompts only; shots take appearance from the reference image.

```
CHARACTERS   emma — Chinese woman, mid-20s, slim, long black hair loose, emerald green dress (speaks)
             brother-2 — Chinese man, early 30s, gaunt, in a wheelchair (exposition-only)
LOCATIONS    suite — hotel suite, floor-to-ceiling window over the city, cream sofa, low table   light: night, morning
PROPS        jug — tall pewter jug, dented, dark handle, carried by emma
```

**Location sheet, one per staged location.** Name every element once; every position, camera and background in the plan is named against it; never `UNKNOWN`. A light line is one sentence of physical facts — the sources and where they fall from — never a colour temperature (no warm, amber, golden, orange) unless the script names the colour; reused verbatim in the plate and every chunk at that state.

```
LOCATION SHEET — suite
Layout:        one long room; entry door at the east end, window wall at the west end
Entries/exits: entry door (east); bedroom door (north wall, mid-room)
Key elements:  cream sofa facing the window; low glass table before it; drinks cabinet by the bedroom door
Depth axis:    door → sofa → window; the city fills the far end
Light states:  night — two table lamps either side of the sofa, window dark with scattered city lights, the room falling off softly toward the door
               morning — flat grey daylight through the whole window wall, lamps off, no hard shadows
```

**Pick the models.** List the studio's image models and video models from its workflow list as it stands now — never from memory, never a model the list does not show — one line each: its title, what it takes in (prompt only, reference images, a first frame, an audio track, a reference video) and its longest clip for video. Mark one of each **(recommended)**: for images the one that takes reference images, if any does; for video the one with the most reference image slots that takes a reference audio. If no listed image model takes reference images, say in one line that sheets, plates and anchors will then be made from words alone and faces will not match across them. Asking for the model is the one setting this skill always asks for — even where the studio's rules say never to ask for a setting.

**The one message.** Show the inventory as a short list (names and one visual line each, not the sheets), ending: **One question, then I run to the finished film, pausing only for you to review the anchors and, before the render, the clips: dump any character, prop or location images you already have (say which is which); strike any exposition-only entry you'd rather not picture; pick one image model and one video model from the list above (or say `recommended`), and how a chunk is cut into its shots — `keyframes` (exact cuts, stiller wides) or `one clip per shot` (free motion, about twice the seconds); set this chat's generation permission so image and video calls run without a card each; reply `go`. Anything not attached, I generate — except flashback looks: for those I'll ask you first.** Silence is not `go`, and `go` without a model pick is answered with the list again — never a model chosen for the user.

## 2 — Map, then listen

**Import first** (on `go` or any message with images). `ffmpeg_job` only accepts Frameo CDN links (`content.dashtoon.ai`), never an external URL. So before anything else, every user image that is not already a Frameo CDN link — a link in the chat, a CSV or tracker row, any outside host — is brought in with `view_image` at `default`, all in one response: the result's snapshot URL is its Frameo CDN copy. Each result belongs to its own call: pair it with the source link in that call's input, never by its place among the results. A call that errors, or whose picture you cannot actually see, is re-run on its own until you can; an image you have not seen is never mapped. Save each to state under `/motion/assets/imports/<n>` (name → source link → CDN link); from here on only the CDN link is used, never the external one.

**Map.** Bind each imported image to a slug. An image the user named — its CSV or tracker row, or "this is X" — is bound to that name's slug through its source link, never by what it looks like or where it sits in a list; only unnamed images are bound by looks. A user character image rewrites its visual line to what is seen: if it is already a sheet (front full-body + close-up), it is that character's sheet; if it is a single picture of the person, it is that character's `photo` and gets a sheet made from it in 5.1; a user location image is its reference for every light state and rewrites the location sheet to what the image shows. Save each binding to its `/motion/assets/<slug>`, then post the **asset table** — one ```` ```csv ```` block, header `asset,type,image`, one row per asset (one row per look of a character, e.g. `kabir (bruised)`): its slug, `character` / `location` / `prop`, and its bare Frameo CDN link (never the source link; nothing else in the cell). Anything still unmapped gets a row with image `unmapped`, then one two-option question, **Generate them** / **I'll map them** — `flashback` looks are left out of it; they get their own question below.

**Flashback cast.** Once the mapping is saved, if any character's `flashback` look has no user image, call `AskUserQuestion` as the only tool call in that response — question: "No reference for [name (look), …] in the flashback scenes — please upload one for each."; exactly two options: `I'll upload them` (description: attach them and say which is which) and `Generate them` (description: I make their sheets). A flashback look is never generated before this answer. **I'll upload them** → wait for the images, then Import and Map them like any other and post the asset table again; **Generate them** → their sheets are made in 5.1 like any later look.

**Improve locations?** If any user location image was mapped, call `AskUserQuestion` as the only tool call in that response — question: "Do you want to improve your location assets before I continue?"; exactly two options: `Yes` (description: rebuild them as realistic, real-scale photos of the same place) and `No` (description: use them as they are). Nothing else runs until the answer is in; with no user location image, skip to Resize.
- **No** → go to Resize with the imported CDN links as they are.
- **Yes** → `load_skill` `image-reconstruct` and run it on every user location image, one run per image, all the way to its Step 9. A location image that is a sheet of several views (a 2×2 grid) is rebuilt from its **top-left view only**: in its Step 1 frame just that panel as a single image (its box, anchor = that panel), so the run renders one image and ends at Step 6 → 8 → 9; the other views are never rebuilt. Each location's one rebuilt image replaces the user's in `/motion/assets/<slug>` for every light state, and the location sheet is rewritten to what it shows. Then go to Resize.

**Resize.** One round of the 1500 px `ffmpeg_job`s above for every user image in use — characters, props, and each location's image (the rebuild after a **Yes**, the imported original after a **No**) — all from their Frameo CDN links, all in one response; save each as `ref_1500`. From then on every slot that takes one of these images — plates, the anchors in 5.2, B-roll in a known place, the chunks — attaches only its `ref_1500`; never the external link, the full-size original or an un-resized rebuild. **Name check:** look at every character and prop `ref_1500`; where the sheet has a name printed on it, that name must match the slug it is bound to. A mismatch with another slug's name is re-bound to that slug and saved before anything else runs; a printed name that matches no slug stops the run — ask the user which character it is, and no anchor is made from it until they answer. Then continue to Listen.

**Listen:** one analysis of the master with the full script supplied, even when an SRT exists (the SRT is the clock; only the analysis hears the sounds). Ask for per-sentence NARRATION/DIALOGUE + speaker (matched to script names, with voice gender and rough age) and a SOUND LIST — every sfx, crowd reaction, ambience shift, music bed and silence with `[start – end]`, what it is, and whether words play over it. Line timings come only from the measured transcript section (missing → re-run once; still missing and no SRT → stop and ask for an `.srt`); sound spans from the analysis body, saved to `/motion/transcript/sounds`. Audio wins on words and timing, script on who speaks and where; attribution must agree both ways or is `[GAP]`; an unlisted voice is added to the inventory, generated, noted.

**Line list.** The analysis's `## Transcript (timestamped)` section is measured: one line per sentence, or per the tool's word cap, each `[start – end] speaker: text`. Save every line to its own leaf, `/motion/transcript/lines/<n>` = `{start, end, speaker, text}` (line `L<n>` is leaf `<n>`) — one leaf per line, never one `lines_raw` string — exactly as the section splits it — never merge lines back into sentences — numbered in audio order, with its start and end copied exactly as given: `/motion/transcript/lines/12` = `{"start": "00:41.320", "end": "00:44.980", "speaker": "speaker_0", "text": "Charles said, his voice cracking"}`. Never round, estimate or fill in a time. These line starts, tightened by the speech spans below, are the film's only clock for cuts (an SRT, when supplied, overrides a sentence's start only). Long lists in state are read in pages: `cat` with `offset`/`limit`.

**Speech spans**, straight after the line list and before any planning. The transcript's line edges are loose. When the narrator and a character have similar voices, it can put a character's line 1–2 s early, with narration inside it. So every character line (any speaker but the narrator) gets its real speech measured:
- Call `audio_separate` once on `$state:/motion/inputs/audio`, and save its voice stem to `/motion/inputs/voice`.
- Make one `sandbox` call: `op: "run"`, `compute: "cpu"`, `files` = `vad.py` (below) and `jobs.json` = `[{"id": "master", "file": "voice.wav", "lines": [{"n": <n>, "start": <s>, "end": <e>, "speaker": "<name>"}, …]}]`, with every line of `/motion/transcript/lines` in seconds and the narrator's speaker written as `narrator`, and `command` = `curl -fsSL -o voice.wav <the stem's https CDN link> && uv run --with numpy python vad.py`. No other fields.
- The script prints each character line's speech span. It drops the narration around a line, and where a character's line runs straight into their own next line it splits them at the transcript's boundary. Save each span to `/motion/transcript/speech/<n>` = `[s, e]`, copied from the output, never computed by hand. A character line missing from the output gets no span and keeps its transcript times; say so in one line.
- From here on, a line with a speech span uses it as its start and end everywhere: unit timing (5.3), the line times in chunk prompts (5.5) and lip alignment (6.0).

The speech scan (`vad.py`), also used in 6.0:
```python
import json, subprocess, numpy as np
def env(p):
    raw = subprocess.run(['ffmpeg','-loglevel','error','-i',p,'-vn','-ac','1','-ar','16000','-f','s16le','-'], capture_output=True, check=True).stdout
    x = np.frombuffer(raw, np.int16).astype(np.float32) / 32768
    n = len(x) // 160
    return np.sqrt((x[:n*160].reshape(n, 160) ** 2).mean(1))   # 10 ms RMS
def runs(r, a, b, thr, gap=0.25):
    out, s, last = [], None, None
    for k in range(int(a*100), min(int(b*100), len(r))):
        if r[k] >= thr:
            s = k if s is None else s; last = k
        elif s is not None and (k - last) / 100 > gap:
            out.append([s/100, (last+1)/100]); s = None
    if s is not None: out.append([s/100, (last+1)/100])
    return out
res = {}
for j in json.load(open('jobs.json')):
    r = env(j['file']); thr = max(r.max() * 0.03, np.percentile(r, 10) * 4, 0.002)   # 3% of peak or 12 dB over the noise floor
    if 'lines' not in j:
        res[j['id']] = [runs(r, a, b, thr) for a, b in j['windows']]; continue
    # speech spans: split runs where a character's line meets their own next line, give each piece to the line it overlaps most
    L = sorted(j['lines'], key=lambda l: l['start'])
    cuts = [(a['end'] + b['start']) / 2 for a, b in zip(L, L[1:]) if a['speaker'] == b['speaker'] != 'narrator']
    pieces = []
    for s, e in runs(r, 0, len(r) / 100, thr):
        pts = [s] + [c for c in cuts if s < c < e] + [e]
        pieces += list(zip(pts, pts[1:]))
    ov = lambda p, l: min(p[1], l['end']) - max(p[0], l['start'])
    spans = {}
    for p in pieces:
        best = max(L, key=lambda l: ov(p, l))
        if ov(p, best) > 0 and best['speaker'] != 'narrator':
            s0, e0 = spans.get(best['n'], (p[0], p[1]))
            spans[best['n']] = (round(min(s0, p[0]), 2), round(max(e0, p[1]), 2))
    res[j['id']] = spans
print(json.dumps(res))
```

## 3 — Anchor

A scene = one continuous stretch at one location. Before any image is planned, each scene gets one ANCHOR: a single wide still of the whole composition — every character present, whole in frame, in place, props in hand, the space legible around them — attached first to every chunk of that state. The anchor is the blocking; nothing else places anyone. A movement beat closes the state, and so does a look change to anyone in it; the next state gets its own anchor, generated from scratch with a full prompt for the new positions, never from the previous anchor.

**Anchor prompt, one per staging state.** Plain words, world-space, no left, right or screen: for each character present — every one, by name, none left to "the others" — the element they are at, posture, facing, the props in their hands, anything binding them (rope, cuffs, a hand gripping them) and which side an injury is on, and their relation to the others in body terms — "kneeling two paces before him, facing him", "the desk between them", "a pace behind and to his left"; distances in body scale, never metres or frame fractions; the light line verbatim. Light is set by the script's words and inherited until the script changes it; props stay in the hand that took them until a beat puts them down; positions change only through a numbered movement beat. When the script has one character look down on, stand over, lean toward or turn from another, the anchor makes it physically true — standing over kneeling, not seated across a desk. A carried prop shown on a character's sheet is that sheet's; it gets no prop sheet and is never re-described.

**Camera side and setups, written against the anchor.** The anchor is taken from one side of the line between the two main characters, at eye level, wide enough that everyone is whole; that side is the camera's side for the state, and left and right in every setup are read off the anchor. Every state has these setups, written once — for two main characters, eight: (1) the anchor's own view; (2–3) front and three-quarter for the first character; (4–5) front and three-quarter for the second; (6) one profile, both side-on; (7–8) an over-the-shoulder each way — only when the two stand within about two paces of each other in the anchor. Farther apart, the state has no over-the-shoulder setups (an over-the-shoulder pulls them together and breaks the blocking); wherever an over-the-shoulder is called for below, that state uses a two-shot or the listener's close instead. One character alone: anchor view, front, three-quarter, profile. A third main character adds their own front and three-quarter. Each setup names where the camera stands relative to the anchor's view ("the anchor's own view", "moved to beside the desk, looking back"), how the subject's head is turned relative to the lens — written as camera geometry and eyeline, never anatomy: front "camera straight in front of him at eye level; he looks just past the lens toward <the other>", three-quarter "camera about 45° off his right side; his head turned away from the lens toward <the other>", profile "camera level with him at his side, 90° to his gaze; he faces across the frame toward <the other>" — its height, what is foreground, what is background, and which side of frame each character falls on and what stands between them and the lens. A **front setup**: the camera on the axis at the other character's position, the subject facing the lens, eyes just off it toward the other — a line said straight at someone, a plea, a threat, a reveal plays here. The **profile setup**: the camera at a right angle to the line between the two main characters, both side-on — a face-off two-shot with the gap between them, or a single profile close of one looking at the other, turning away, or thinking. About 10–15 % of a scene's units play on it. A setup is the only place left and right exist. If a state must change side, a neutral unit — a frontal close, an insert, or a setup on the axis between the two — sits between the last setup on the old side and the first on the new; never a bare swap.

## 4 — Plan

Units = one shot each, in audio order. **Each unit names the transcript line it starts on** — `from: L<n>` from `/motion/transcript/lines` (a sound unit with no line names its measured sound start instead: `from: sfx@<start>`; a unit in a wordless gap names the line the gap follows: `from: gap@L<n>`; a unit in the wordless lead-in before the first line: `from: gap@start`; a unit in the wordless tail after the last line: `from: gap@end`). A cut can only fall at the start of a line, or inside a wordless gap: a unit covers one line or several consecutive lines and runs until the next unit's line; no unit writes a time of its own. The words ÷ 2.5 (narration) / ÷ 3 (dialogue) estimate is only for sizing units to the pace below, never a timecode.

**Shot size, decided line by line from the words, to this split per scene: close 35–45 %, medium (incl. two-shot and over-the-shoulder) 25–35 %, the rest — wide, mid, insert — at most 40 %, no floor.** A scene outside the split is re-cut before it is saved. Save a per-scene tally of sizes with the plan.

- **Medium** — the default: any unit that matches none of the cases below. Two people interacting → two-shot or over-the-shoulder; one person alone, or an aside about them → single. The fallback, not the majority.
- **Wide** — when a character's whole body moves or changes position (walks in, turns to leave, kneels, collapses, stands up), or big spectacle (explosions, tanks). Every scene and staging state opens on one (see the opening row). A line that mentions the crowd or the family does not make it a wide, and wides are not on a schedule — a dialogue scene can go a minute or more without one.
- **Close** — when the line is about one person's face or voice (their expression, their eyes, how they said something — "hissed", "sneered", "his face twisted"); a line said straight at someone that lands (a question, a threat, a plea, a reveal, an order, an insult); and the listener's reaction unit after such a line. No more than three closes in a row, then a medium or wider.
- **Insert** (extreme close-up) — when the narration names a hand or object being used ("grabbed the phone", "slammed her glass down", "fists clenched"); eyes or mouth as the subject → an insert of that part of the face. An object only mentioned in dialogue ("Polish my shoes") gets no insert. About one every 15–20 s, usually between two shots of people, never two in a row.
- **Pace** — about 30–35 shots per minute; holds of about 1.5–2.5 s, 1.2 s at the shortest, nothing past ~3 s; every cut shows a new thing the words name or a reaction to them.
- **Angle** — eye level 70 % or more; low only on who holds the scene, high only on who is diminished or on a crowd from behind the lead; overhead on inserts only. No single setup carries more than a third of a scene's units, and two consecutive units never share a setup — the camera moves on every cut. When a character comes back after a cut away (A → B → A), the return uses a different setup from that character's last shot: front, then three-quarter or profile, never the same angle twice in a row for the same person. The same character may hold several shots in a row as long as each one looks clearly different from the one before: a change of size (wide → close → medium), of setup (front → profile), or both — never just an expression change on the same framing.

**Sequences the words describe rather than show.**
- **B-roll, montage, flashback** — when the narration explains something not happening in the scene (background, facts, an idea, the past or future) or goes inside a character's head (their beliefs, opinions, tastes, what they love or hate, a list of examples — "love letters, flowers, a song"), the shots follow what the narration names, one beat per shot — each named thing, person or example its own shot — each flagged `[ENHANCED]`. B-roll pictures only what the narration is literally about, never its figures of speech: in a comparison or metaphor ("like a symphony", "a siren unleashed", "two halves made for his hands") the thing compared to is never shown — the shot is of the real subject (the woman, the kiss, the moment), with the comparison's feeling carried by expression, light and framing. A shot works when, with the sound off, it still belongs in this story's world; an orchestra, a mythical siren or any object that exists only in the comparison fails. A long stretch of such narration is never held on the character it is about: at most one in three of its units goes back to them. Generic people and things the narration names (women, a man raising his hand to a woman, a bouquet, a letter) need no sheet: they are described directly in the prompt, in the episode's setting. These are **independent shots**: no staging state, no anchor. They form their own chunks (5.4), generated from the sheets of the characters they show (the look of the time they show — a flashback before a change uses the earlier look), plus the location's plate when it happens in a known place; their prompt describes the place directly.
- **Action** — one wide that shows who is where and where the threat is, then the events in the order they are told, one beat per shot: cause first, then effect.

**4.1 Cut the units.** The unit is the clause, not the sentence: split a narration sentence wherever a clause names a new thing — an object, a body part, an action, a place, a reaction — at the transcript line start nearest that clause (the next one, never an earlier one, so a picture never shows what has not been said). Aim for 4–6 words a unit (1.5–2.5 s); merge under ~1.2 s into a same-location neighbour, split anything past ~2.5 s. A dialogue line over ~2.5 s is two units. A line that lands — a question, a threat, a plea, a reveal, an order, an insult — is followed by the listener's reaction unit before the next line, even when the same speaker continues.

Never ahead, never behind: a unit may not show what its line has not yet named. An unplaced speaker (phone, through a door) is at their last location. Narration about an absent place or person → a unit from its plate or sheet, flagged `[ENHANCED]`.

**4.2 No reuse.** Every unit is its own shot inside its chunk; nothing is replayed. A character's shots cycle through their setups (front, three-quarter, profile, over-the-shoulder), never ping-ponging between two frames, and each carries a full expression read from the line and the conversation's prevailing feeling for them — never a blank or generic face.

**4.3 Direct each unit.** A unit picks and writes no geometry of its own. **setup** — one of the state's setups, by id; for `close` and `insert` only its camera side, height and the direction the other character falls in are pasted — its foreground and background description is left out, because scenery text widens the frame. **shot** — `insert` (one part or object, nothing else) · `close` (the face alone, cropped into the forehead and through the neck; written in the prompt as "extreme close-up of the face") · `medium` (waist up) · `ots` · `two` (one nearer, one further) · `mid` (full body) · `wide` (the whole space, and everyone in it when they are there); dialogue is close, medium, ots or two; wide or mid only when the speaker's whole body moves on the line (stands, kneels, turns to leave). **angle** — `eye` unless the angle rule gives a reason: `low` for the character who holds the scene, `high` for the one diminished, kneeling or seated below the other; it names the setup's height, never a new camera. **action** — the line made physical: with the sound off, the picture alone should say what is being heard (a demand is a finger jabbing or a palm slapping the desk, a confession is eyes dropping and hands twisting, a sum of money is the body bowing lower as it is named); a generic talking or standing pose fails even with the mouth open. It is what the words have the character doing at this instant, stated or implied — a threat leans in, a plea opens the hands, a reveal makes the other go still, a dismissal turns the body away — caught mid-gesture at or just before its peak, **in place**: a hand mid-gesture, a head turning or coming up, shoulders dropping, a lean from where they are, a hand reaching; nobody walks, stands up, sits down or changes spot inside a state — that is a movement beat and a new anchor; a speaker mid-word; a listener reacting with the face or hands, not waiting. Nobody stands or sits at rest unless the text says stillness; when the text gives no verb, the character continues the business the anchor prompt gave them (holding, leaning, pouring). **The action is sized to the unit's length** (its line span, the words ÷ 2.5 estimate until 5.3 times it): a unit under 2 s holds **one quick beat** — a blink, a brow lifting, a glance, a hand closing, a petal letting go; a unit over 3 s holds **one slow continuous action that is still going when the cut comes** ("her hand drifts toward his palm, still hovering above it"); between them, one action that fills the shot. Nothing that has to finish — crossing and turning back, picking up and putting down, two actions in a row — goes in a unit under 3 s; write its start only ("begins to turn his head"). **pose** — the body follows the words and the scene: the posture is the one the anchor shows; the narration and the line only shade it (hunched, arms folded, head bowed, shoulders squared) — a change of posture that moves the body (kneeling, rising from the chair) is a movement beat and a new anchor; a posture the line implies (an order squares the shoulders, shame drops the head, a plea bends toward the other) is shown; it changes only when the words or a movement beat change it. **face** — two parts. Mouth and eyes: whenever the character is speaking during the unit, the mouth moves with the words — no exception; speaker "mouth open mid-word, eyes to frame [left | right] (or just off the lens on a frontal setup, or straight across the frame in profile on the profile setup), on <the other, by tag>"; listener "mouth closed, eyes to frame [left | right], on <the speaker>"; thinker "mouth closed, eyes down"; the side is read off the unit's setup, the direction the other character falls in from that camera. Then the expression, read from this line and the narration around it — what the character feels about what is being said or done right now, and to whom; any face, voice or feeling word the narration uses ("sneered", "trembling", "his voice cracked") decides it. Write it as one emotion word followed by 2–4 snippets from the **expressions** presets, pasted verbatim (a `recipe-` combination when one fits the moment, otherwise single brow, eye, mouth and head items stacked): "cold fury: eyebrows pulled down and together shadowing the eyes, lower eyelids tensed and raised, lips pressed firmly together". Search the expressions category only, all searches in one round before the chunks; other preset categories are never searched. Never neutral: every face is in the middle of feeling something the words gave it. **picture** — names the subject by where they are in the anchor ("the man kneeling in front of the desk"), never re-describing the blocking, then the action, then props by visual tag, no mood words. A prop a character holds through the state (a phone on a call, a glass, a weapon) is named in every unit that shows them, with where it is ("the phone pressed to her right ear"), until a beat puts it down; on a `close` it stays in frame at the edge ("the phone at her ear, its edge in frame"), and a "free hand" is only the hand not holding it; it ends with the size's fill clause — `close`: *"extreme close-up: the frame is cropped at the forehead just above the brows and at the chin, the bottom edge cutting across the neck below the jaw; the face fills the frame edge to edge, eyes on the upper third line; the room is no more than a blurred sliver at the corners, nothing else in focus"*; `medium`: *"the subject fills the frame from the waist up, head near the top edge, the room out of focus behind"*; `ots`: *"the near shoulder fills a third of the frame, soft; the far subject sharp from the waist up"*; `mid`: *"the full body fills the frame's height, feet near the bottom edge"*; `insert`: *"the [part or object] fills the frame edge to edge and sharp, the room a soft blur behind it"*; `two` and `wide` take their positions from the setup. **move** — the camera move during this shot, chosen from what the shot is about, never by rotation. Every move is very slow and steady:
- `zoom-in` — the push for emphasis: closes and inserts on an emotional beat (a smile, a bruised face, a reaction that lands, a mouth on a line about the voice) and close shots of objects in use (a fist clenching, a radio in a hand, a glass poured). The most used move, about a quarter.
- `zoom-out` — reveals: wides and establishing shots, one character standing over another, spectacle arriving (tanks, jets), someone stepping back or into shadow, two-shots of dialogue, and the last shot of the film. About a fifth.
- `pan-left` / `pan-right` — dialogue singles and over-the-shoulders, and inserts of hands and props. The direction is never arbitrary: pan the way the subject looks (leading their eyeline toward the other character), or the way the action or object travels. About a third between them.
- `tilt-down` — things falling or submitting: kneeling, bowing, a head dropping, a slap landing, debris, looking down on someone, a gaze following something to the floor. About one in twelve.
- `tilt-up` — looking up at power or rising things: a low-angle shot of whoever holds the scene, someone standing up, smoke rising, a gaze travelling up from the floor to a face. About one in twelve.
- `static` — stillness: an establishing wide of a group, a frozen beat or a silence the words name, an object at rest. About one in twenty.
Consecutive shots never share a move.

**extras** — when the scene needs unnamed people: how many, doing what, how soft; never a named character's face or outfit, never the eye unless the sound or line is theirs.

**on_screen_speaker** — the name of whoever speaks on screen during the unit (a dialogue line, the speaker in the scene); none for narration, off-screen and phone voices. It decides which lines the chunk prompt names as spoken on screen (5.5) and which get lip alignment (6.0).

**Final check, before anything is generated.** When a scene's plan is done, walk its whole shot list once and fix every break: two neighbours that look alike (same size and setup, or an expression change on the same framing), a character returning on the angle of their last shot, a size split outside its range, a pace window broken (30–35 shots per minute), a unit whose `from` line is not in the line list, or starts before the words its action shows, a character on a look that is not the one in force at the unit's `from` line in their look list. Then save the scene to `/motion/plan/scenes/<n>` (with the size tally and every `[FIXED]` / `[GAP]` / `[ENHANCED]`) and each unit to `/motion/plan/units/u<n>`, and continue; only a `[GAP]` that changes who speaks or what is shown stops the run.


## 5 — Generate

**5.1 References for the gaps, all at once.** Anything seen twice gets a reference before any chunk; a user sheet is never regenerated. A character with a user `photo` gets its sheet here first: the prompt below, opened with "Same person as @reference_image1 — same face, hair and outfit.", with the photo's `ref_1500` attached as the only reference; that sheet, not the photo, is used from here on. Every call here runs on the chosen image model (`/motion/decisions` `image_model`), written out, at its draft quality, `1:1`, up to 2K. Each later look gets its own sheet: @reference_image1 is the previous look's sheet (it carries the changes so far), @reference_image2 is the face source — the user's `photo` `ref_1500` when there is one, otherwise the character's `base` sheet — never a chain of sheets alone; the prompt below, opened with "Same person as @reference_image1, same face as @reference_image2 — now [the look's change line].", the [visual line] carrying the change. Character sheet (one per character and look):

**5.3 Timestamps, copied from the line list.** The clock is `/motion/transcript/lines` (the SRT, when supplied, overrides a sentence's start only). Long lists in state are read in pages: `cat` with `offset`/`limit`. Each unit's `tc_in` is the measured start of its `from` line, copied exactly from state: the start of its speech span (`/motion/transcript/speech/<n>`) when it has one, otherwise its line start — never estimated, rounded or worked out from durations; a sound or scene-building unit copies its measured sound start. If a timestamp cannot be read from state, stop and say which unit. The first unit starts at 0.000. Gapless grid, `tc_out(n) == tc_in(n+1)`, the last unit ending at the master's exact end, all on the 24 fps grid; silence between lines under 3 s belongs to the unit before it. A gap of 3 s or more belongs to its `gap@L<n>` units: they span L<n>'s `end` + 0.5 s to the next line's `start` and divide it evenly, wide first — the unit before keeps only L<n> and that 0.5 s tail. The ends of the film work the same way: `gap@start` units span 0.000 to L1's `start`, the wide first; `gap@end` units span the last line's `end` + 0.5 s to the master's end — each divided evenly. A line the audio never speaks → dropped; an audio line the plan lacks → absorbed, or one extra unit if ≥ 3 s. Sound units under 1.5 s are dropped. A unit shorter than 1.2 s merges into its neighbour in the same state (a shot under 1.2 s does not read). `f_in = round(tc_in×24)`, `f_out = round(tc_out×24)`; Σ (`f_out − f_in`) = the master's frame count. **Check:** every `tc_in` (except 0.000 and even-split gap units) must equal a speech start, line start or sound start in state; any that does not is re-copied from its `from` line. Any unit longer than 3.5 s, except a wordless-gap unit and the establishing wide (3 s at most), is a pace break: go back to 4.1 and split it at the next clause before saving. **5.4 Chunks and their audio.** Walk the units in order and group consecutive ones into **chunks** — one `video_create_edit` call each. A chunk:
- holds units of one staging state only (one anchor) — a state change, a location change or a look change always starts a new chunk; independent B-roll, montage and flashback units form their own chunks, never mixed with anchored units — except a B-roll run shorter than 4 s between anchored units, which joins the anchored chunk it sits in: its shot line opens "cutaway, away from the room:", describes its own subject and place, and names only its own references, never the anchor;
- runs from its first unit's `f_in` to its last unit's `f_out`, at most **15 s** (or the chosen model's longest clip, if shorter) and at least **4 s**; a state shorter than 4 s is still one chunk, generated at 4 s and trimmed;
- ends where a unit ends, at the best break before the cap: a speaker change, then the end of a line, then a pause — never inside a line; aim to fill the cap, but a short chunk at a natural break beats a long one that splits a line from its reaction;
- fits its references in the chosen video model's image slots (the anchor once, then every sheet and prop its units need, each once) — if not, end the chunk one unit earlier.

`duration` = the chunk's span in seconds rounded **up** to a whole second, never under 4; the extra is trimmed at render.

**Chunk audio** — every chunk, with or without dialogue, gets its own slice of the master: from `f_in / 24` to `f_out / 24`, the chunk's exact span, narration, music and sound included. **Track chunks and their timing track.** A chunk with no `on_screen_speaker` in any of its units is a **track chunk**; a chunk with any line spoken on screen is a **dialogue chunk** and keeps the timestamped prompt with @Audio1 (5.5) — its mouths need the voice. ## 6 — Render

**6.0 Lip alignment, before the trims.** The video model voices the on-screen lines on its own clock. It usually starts the line at the top of its shot rather than at the line's time, and it often speaks 1.5–4× faster than the master. The trims in 6.1 therefore retime every chunk that has dialogue, so each mouth opens and closes on the master's words. No chunk is re-generated, and no lipsync tool is used. Chunks with no line spoken on screen (`on_screen_speaker`) — every track chunk — skip this step.
- **Master speech spans** are read from `/motion/transcript/speech/<n>`, measured in step 2. A line without one uses its transcript `start`–`end`.
- **Clip speech spans.** Clip audio carries ambience, breaths and sobs, so the scan alone cannot tell which sound is the line. Every dialogue chunk's clip (`$state:/motion/clips/c<k>`) gets one `video_audio_analysis` call, all of them in one response, asking for the exact `start – end` of each quoted line in the clip, to 0.1 s. Then run the speech scan on the clip's audio over each reported span ± 0.4 s. The line's clip span runs from the first to the last active run that overlaps the reported span. A line the analysis cannot find, or one with no active run, leaves the chunk with no map: it is trimmed plainly and named in the delivery.
- **Scan.** One `sandbox` call for all the dialogue chunks' clips, shaped as in step 2 (**Speech spans**), running the same `vad.py` with `"id": "c<k>"` jobs; `command` `curl`s each clip's https CDN link to `c<k>.mp4` before `uv run`.
- **Segment map**, in chunk-local seconds. The target times are the master spans minus `f_in / 24`, and the source times are the clip spans. The chunk alternates gap, speech, gap, …, gap. Each speech segment is stretched or squeezed to its master span, at a factor `target ÷ source` clamped to 0.67–2.0. The clamp is fixed and is never widened, whatever the result. Past the clamp, only its start is aligned, and the rest of the time goes to the next gap. Each gap fills the time between the speech segments. If a gap's source is longer than its target and the speed-up would be ≤ 1.4×, it is played faster. Beyond 1.4×, the excess is cut at 1:1, from the start for the opening gap and from the end for any other gap. A gap whose source is shorter than its target is stretched. Save the map to `/motion/lipsync/c<k>` = `{lines: {L<n>: {master: [s, e], clip: [s, e]}}, segments: [[src_s, src_e, factor], …]}` before 6.1. A tiny offset needs no map: when every line in a chunk is already within 0.1 s at both ends, the chunk is trimmed plainly. `sandbox` only ever runs the speech scans, here and in step 2. Every trim, join and proof sheet stays an `ffmpeg_job`, exactly as 6.1 and 6.2 write it.

**6.1 Trims, in parallel.** One `ffmpeg_job` per 10 chunks, every job in one response, one output per chunk, named `c<k>.mp4`; input `asset_ref` `$state:/motion/clips/c<k>`. Each chunk is cut to exactly its span from its own start, video only — the clip's own audio is always dropped:

```
-i <c_k> … -map 0:v -vf "fps=24,trim=end_frame=<f_out−f_in>,setpts=PTS-STARTPTS,scale=1080:1080:flags=lanczos,setsar=1,format=yuv420p,tpad=stop_mode=clone:stop=<pad>" -an -r 24 -c:v libx264 -crf 18 -preset medium -profile:v high -level 4.2 -pix_fmt yuv420p c<k>.mp4  -map 1:v …
```

A chunk with a `/motion/lipsync/c<k>` map uses this filter instead: one `trim` per segment, then exactly `<f_out−f_in>` frames. Segments slowed by more than 1.15× also get `minterpolate`, and any rounding shortfall is padded by holding the last frame:

```
-i <c_k> -filter_complex "[0:v]fps=24,split=<n>[a1][a2]…;[a1]trim=start=<s1>:end=<e1>,setpts=(PTS-STARTPTS)*<f1>[s1];[a2]trim=start=<s2>:end=<e2>,setpts=(PTS-STARTPTS)*<f2>,minterpolate=fps=24:mi_mode=mci:mc_mode=aobmc:me_mode=bidir:vsbmc=1[s2];…;[s1][s2]…concat=n=<n>:v=1:a=0,fps=24,scale=1080:1080:flags=lanczos,setsar=1,format=yuv420p,tpad=stop_mode=clone:stop=24,trim=end_frame=<f_out−f_in>,setpts=PTS-STARTPTS[v]" -map "[v]" -an -r 24 -c:v libx264 -crf 18 -preset medium -profile:v high -level 4.2 -pix_fmt yuv420p c<k>.mp4
```

**Track chunks are retimed, not padded.** An edit of a timing track comes back evenly sped up — about 7 frames short over the whole clip, every cut slightly early — so its trim first stretches it back to the track: `setpts=PTS*<r>,` placed at the very start of the plain-trim filter, before `fps=24`, with `r` = the track's frame count ÷ 24 ÷ the clip's reported duration (4 decimals), and `<pad>` = 0. A track chunk whose clip is more than 12 frames short or long after that stretch is re-rolled.

For a plain trim, `<pad>` = 0 when the clip's reported duration covers the span; when it runs short by ≤ 12 frames, `<pad>` = the missing frames (the last frame held); short by more → re-roll the chunk, never pad. Save each output to `/motion/render/trims/c<k>`. Then check: the trims in chunk order cover u001…uN with nothing missing or repeated, and Σ trimmed frames = the master's frame count.

**6.2 Join.** One job: ffconcat of the trims in chunk order from `/motion/render/trims`, stream-copied, hard cuts, with the master from `/motion/inputs/audio` as the only audio track, plus proof sheets from the same input — the frame at the midpoint of every unit (from `/motion/timing`), unit id and timestamp burned in, 384 px tiles, 6 per row, ≤ 60 per sheet. Save the film and sheet links to `/motion/film`. **Subtitles only when the user asks** — the first delivery has none; when the user asks (now or after delivery), re-run only this join with the cues burned in (encoded with the trim settings), and save that film and the cue list to `/motion/film_subs` — `/motion/film` stays the clean film. The cues are burned in once, through `ass=subs.ass:shaping=complex` from a `subs.ass` sidecar with this exact header and style (PlayRes 1080 scales it to any square film). The style is fixed: whatever font, size, colour, position or look the user asks for, burn in this one unchanged and say in one line that Pocket Motion (Seedance) uses its house subtitle style:

```
[Script Info]

PlayResX: 1080
PlayResY: 1080
WrapStyle: 2

[V4+ Styles]
Format: Name, Fontname, Fontsize, PrimaryColour, SecondaryColour, OutlineColour, BackColour, Bold, Italic, Underline, StrikeOut, ScaleX, ScaleY, Spacing, Angle, BorderStyle, Outline, Shadow, Alignment, MarginL, MarginR, MarginV, Encoding
Style: Pocket,Poppins,66,&H0004BCFC,&H0004BCFC,&H00101010,&H99000000,-1,0,0,0,100,100,0,0,1,1.8,2.8,2,60,60,45,1

[Events]
Format: Layer, Start, End, Style, Name, MarginL, MarginR, MarginV, Effect, Text
```

Cues: one `Dialogue: 0,<start>,<end>,Pocket,,0,0,0,,<text>` per line of `/motion/transcript/lines` — a line too long for two rows splits at the word nearest the middle; a cue never spans two lines; each cue timed from its line's start and end split by character count, times as `H:MM:SS.cc` on the master's clock; sound and gap units get none. **Speech span first:** a line's words need words ÷ 2.5 s (narration) or ÷ 3 s (dialogue); when its span runs more than 2 s longer than that, the extra is music or silence, not speech — on the film's first line and the first line after a scene cut it sits at the front (the cues start at `end` − that need), on any other line at the back (the cues end at `start` + that need). Split the cues over that speech span, never over the music. ≤ 28 characters a row, ≤ 2 rows, broken with `\N` at a word boundary nearest the middle — a cue that still overflows drops to the word count that fits. **Deliver** when the film's duration equals the master's within one frame: the film and the proof sheets, plus one line naming the retimed lines that run more than 1.5× slow and any dialogue chunk trimmed without a map; the user asks for changes by naming a unit or a time.

## Editing after `go`

A named shot → re-roll its whole chunk once, with the change written into that shot's line, same references and audio (a track chunk: same references and track) — then redo its 6.0 map (dialogue chunks) or its retime (track chunks), re-trim that chunk and re-join. A look change to a character, prop or light → its sheet, plate or light line, then every chunk using it; say how many first. An anchor change (a moved character, a re-rolled anchor) → the anchor, then every chunk of that state; say how many first. Every redo overwrites its path in state, adds a `/motion/log` line, and is rendered only from state. Nothing else is touched.
